# Data Model: Web Console Shell and LLM Profiles

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Research**: [research.md](research.md)

Entities from the spec's Key Entities, with the fields, rules, and state transitions the plan
gives them. Python names are the planned ones; API shapes are in
[contracts/openapi.yaml](contracts/openapi.yaml).

## Entities

### Provider (`Provider`, in `llm/providers.py`)

A fixed table, one row per provider a saved profile may use (FR-004). It is the only place a
provider's names appear (research R3).

| `id` | Label in the console | Model string prefix | Variables the environment's profile reads | Its own address | Has the API choice |
|---|---|---|---|---|---|
| `openai` | OpenAI-compatible | `openai:` | `OPENAI_API_KEY`; `OPENAI_API_BASE`, then `OPENAI_BASE_URL` | `https://api.openai.com/v1` | yes |
| `anthropic` | Anthropic | `anthropic:` | `ANTHROPIC_API_KEY`; `ANTHROPIC_API_URL`, then `ANTHROPIC_BASE_URL` | `https://api.anthropic.com` | no |
| `openrouter` | OpenRouter | `openrouter:` | `OPENROUTER_API_KEY`; `OPENROUTER_API_BASE` | `https://openrouter.ai/api/v1` | no |

The base URL variables are the ones the provider's client reads, in the order it reads them;
the environment's profile shows the first that is set. A provider's own address is where a
saved profile with no base URL is sent: it is passed to the client, which would otherwise take
an address from those variables.

A saved profile's provider is one of the three ids. The environment's profile may carry any
prefix LangChain accepts; one outside the table is shown as written, with no key hint and no
base URL, and is not offered in the form.

### LLM profile, saved (`LlmProfileRecord`, table `freyja_llm_profiles`)

One way to reach a model, saved by an operator.

| Field | Type | Rule |
|---|---|---|
| `id` | text, primary key | 32 hex characters, generated by the service; never `environment` |
| `name` | text | 1 to 64 characters after trimming; unique without regard to case (unique index on `lower(name)`); never the reserved name of the environment's profile (FR-006) |
| `provider` | text | `openai`, `anthropic`, or `openrouter` (FR-004) |
| `model` | text | 1 to 200 characters after trimming (FR-006) |
| `base_url` | text, null | at most 2,000 characters; `http` or `https` with a host; any host is allowed (spec Assumptions, trust) |
| `api_key_encrypted` | text | the key as a Fernet token under `FREYJA_SECRET_KEY` (research R4); never leaves the store module in any other form than the decrypted key handed to the model factory |
| `key_hint` | text | the key's last four characters, or empty when the key has fewer than eight (FR-020); stored in clear so a card can be shown without the secret |
| `responses_api` | boolean, default true | used only when `provider` is `openai` (FR-004); stored and ignored for the others |
| `config_version` | integer, default 1 | incremented when `provider`, `model`, `base_url`, the key, or `responses_api` changes; not when only `name` changes (FR-019a) |
| `last_test_ok` | boolean, null | null: not tested since the last change of `config_version` |
| `last_test_at` | timestamptz, null | the database's `now()` when the result was recorded |
| `last_test_step` | text, null | `first_message` or `conversation`: the step that failed; null when the test passed |
| `last_test_reason` | text, null | at most 500 characters, with the key removed (FR-021); null when the test passed |
| `created_at`, `updated_at` | timestamptz | the database's `now()` |

Rules:

- At most 50 rows (FR-006). The insert counts the rows under a transaction-level advisory lock,
  so two concurrent adds cannot both pass the count.
- A write that changes `config_version` clears the four `last_test_*` columns in the same
  statement.
- A test result is recorded with `WHERE id = %(id)s AND config_version = %(version)s`, the
  version read when the test started, so a result for values the profile no longer has is
  dropped (spec Edge Cases).
- Concurrent edits: the later statement wins (User Story 4). There is no version check on edit.

### Active profile and revision (table `freyja_llm_state`)

One row for the whole database, created at setup.

| Field | Type | Rule |
|---|---|---|
| `id` | smallint, primary key | always 1 (`CHECK (id = 1)`) |
| `active_profile_id` | text, null | references `freyja_llm_profiles(id)` `ON DELETE RESTRICT`; null means the environment's profile is active (FR-011) |
| `revision` | bigint, default 0 | incremented by every activation that changes the active profile and by every edit of the active profile (FR-013, FR-014) |
| `updated_at` | timestamptz | the database's `now()` |

Rules:

- Exactly one profile is active at every moment (SC-009): the single row holds one value, an
  activation is one `UPDATE` in one transaction, and the foreign key refuses the deletion of the
  row it points at, whatever order two requests arrive in.
- Activating the profile that is already active changes nothing and leaves `revision` alone.
- `revision` is what a service instance compares before each run to know whether the model it
  built is still the active one (research R6).

### LLM profile, environment (`environment_profile()`, never stored)

Built at startup from what the service was started with (FR-008).

| Field | Source |
|---|---|
| `id` | the constant `environment` |
| `name` | the constant `Environment` |
| `provider`, `model` | the two halves of `FREYJA_MODEL` |
| `base_url` | the provider's base URL variable, when set and the provider is in the table |
| `key_hint` | from the provider's key variable, by the same rule as a saved profile |
| `responses_api` | `FREYJA_OPENAI_RESPONSES_API`, when the provider is `openai` |
| `usable` | the model can be built, and the provider's key is set when the provider is in the table (research R3) |
| last test | kept in memory on the instance; cleared when it restarts (FR-019a) |

It has no `created_at` or `updated_at`. Each service instance has its own, read from its own
environment.

### Model in use (`ActiveModel`, in `llm/active.py`)

What one service instance holds between runs (research R5, R6).

| Field | Meaning |
|---|---|
| `revision` | the `revision` this instance last applied |
| `profile` | id, name, and source of the profile the built orchestrator uses, for the run's first event and log line (FR-024a) |
| `usable` | false when no usable model is active (FR-016) |
| `why` | why not, as one of the codes a profile's `unusable_reason` has; null when usable. The list reads `cannot_build` from here, since a key that can be read does not tell whether a model can be built |
| `reason` | why not, as a sentence with the key removed; null when usable |
| `secrets` | the keys text must be cleaned of (FR-021): the active profile's key |

### Profile test (`ProfileTest`, not stored beyond the last result)

One check of a profile or of unsaved form values (FR-017 to FR-019a).

| Field | Meaning |
|---|---|
| `ok` | every step was answered |
| `step` | `first_message` or `conversation`: the step that failed; null when `ok` |
| `reason` | at most 500 characters, the key removed; null when `ok` |
| `at` | when it ended |
| `recorded` | whether the result was kept with a listed profile; false for form values and for a profile that changed or was deleted while the test ran |

Steps, in order (research R7):

1. `first_message`: one user message.
2. `conversation`: the same user message, an assistant turn that calls one tool, that tool's
   result, and a second user message, with the tool's definition attached.

Limits on each service instance (FR-019b): one test in progress per listed profile, and four
in all, counted in memory. A request beyond either is refused with `test_busy` before anything
is sent.

## State transitions

### A saved profile

```text
(none) --add--> saved, not active, untested
saved --edit name--> saved (test result kept)
saved --edit provider | model | base URL | key | API choice--> saved, untested
saved --test passes | fails--> saved, tested (result kept)
saved, not active --activate--> saved, active        [revision + 1]
saved, active --edit--> saved, active                [revision + 1]
saved, active --another profile activated--> saved, not active
saved, not active --delete--> (none)
saved, active --delete--> refused (409 profile_active)
```

Usability is not a stored state (FR-011a). A saved profile is unusable when its key cannot be
decrypted with the current secret, or no secret is set (FR-022); entering its key again makes
it usable. It is worked out by the instance that answers, from the secret that instance was
given.

### The active choice

```text
environment --activate saved P--> P            [revision + 1]
P --activate saved Q--> Q                      [revision + 1]
P --activate environment--> environment        [revision + 1]
P --activate P--> P                            [no change]
```

An unusable profile cannot be activated (409 `profile_unusable`). A profile that is active and
becomes unusable stays active (FR-016).

### A service instance's model

```text
startup: read state --> build from the active profile --> usable | unusable
before every run: read revision
    same     --> run on the orchestrator already built
    changed  --> read the active profile, rebuild the orchestrator, then run
run in progress: keeps the orchestrator it started on, whatever happens meanwhile
```

## API shapes

Defined in [contracts/openapi.yaml](contracts/openapi.yaml): `LlmProfile`, `LlmProfileList`,
`LlmProfileCreate`, `LlmProfileUpdate`, `LlmProfileDraft`, `LlmTestResult`, the added error
codes, and `RunProfile` in the run stream's first event
([contracts/sse-events.md](contracts/sse-events.md)).

Never part of any shape: a key, a Fernet token, or `FREYJA_SECRET_KEY`.
